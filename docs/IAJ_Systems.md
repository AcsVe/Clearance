## 2) البنية المشتركة (كل الأنظمة تعمل بنفس الطريقة)

### أ) التشغيل
- **كمبيوتر المدرسة (ويندوز)** يشغّل كل نظام في مجلده، بخادم **Waitress** (`serve.py`) على منفذه.
- **Python 3.12 (64-bit)** + **Git** مثبتان مرة واحدة؛ لكل نظام `venv` خاص داخل مجلده.
- **Task Scheduler** — لكل نظام ثلاث مهام بحساب SYSTEM:
  | المهمة | التوقيت |
  |---|---|
  | `<النظام> Website` | عند تشغيل ويندوز |
  | `<النظام> Hourly Backup` | كل ساعة |
  | `<النظام> Failover Watchdog` | كل 5 دقائق (إن كان العنوان موجّهاً للهاتف والهاتف انقطع، يعيده للكمبيوتر تلقائياً) |
- منع السكون (`powercfg`) يُضبط تلقائياً من `3_autostart.bat`.

### ب) النشر للإنترنت — Cloudflare
- **نفق رئيسي واحد `iajaward`** على الكمبيوتر يخدم كل العناوين (كل عنوان ← `localhost:<منفذه>`).
- لكل نظام **نفق احتياطي** على الهاتف: `attendance-standby` (ATT)، `bell-standby` (BELL)، وللمكتبة لاحقاً.
- `ops/cf.py` في كل نظام يدير السجلات والتحويل عبر **Cloudflare API** (الرمز `CF_API_TOKEN` في `.env`؛ نظام الجرس يقرؤه تلقائياً من `.env` الخاص بـ ATT).

### ج) الهاتف الاحتياطي (Termux)
- كل نظام في مجلد على الهاتف (`~/attendance`، `~/bell`) بجانب موقع الجائزة `~/iaj` دون تعارض.
- `standby/phone.sh`: `setup` ← `configure` ← `update-code` ← **`takeover`** (الطوارئ: أحدث نسخة من Drive + تشغيل + تحويل العنوان للهاتف).
- أزرار Termux:Widget لكل نظام (ATT / BELL).

### د) النسخ الاحتياطي
- كل ساعة إلى **Google Drive** ← `IAJ-backups\<النظام>` (`attendance`، `bell`)، مضغوطة مع نسخة من الكود.
- يدوياً: `backup_now.bat`؛ الاسترجاع: `restore_backup.bat` (يحفظ نسخة أمان من الحالي أولاً).
- ATT: نسخة ثانية اختيارية في **Neon** (`neon_link.bat`).

### هـ) ملفات التشغيل (نفس الأسماء في كل نظام)
| الملف | العمل |
|---|---|
| `1_setup.bat` | مرة واحدة: venv، المكتبات، `.env`، الجداول، نقل بيانات قديمة، ربط العنوان |
| `2_start.bat` | تشغيل يدوي للتجربة |
| `3_autostart.bat` | **كمسؤول**: البدء مع ويندوز + النسخ كل ساعة + المراقب |
| `update.bat` | **التحديث الوحيد الذي تحتاجه**: سحب من GitHub + المكتبات + إعادة التشغيل |
| `att_on/off.bat`، `bell_on/off.bat` | تشغيل / إيقاف هذا النظام فقط |
| `site_where.bat` | أين يشير العنوان الآن (الكمبيوتر أم الهاتف) + تشخيص |
| `switch_to_server.bat` / `back_to_server.bat` | إرجاع العنوان للكمبيوتر / أخذ بيانات الهاتف بعد الطوارئ |
| `backup_now.bat` / `restore_backup.bat` | نسخ / استرجاع |
| `stop_autostart.bat` | إلغاء المهام |
| `bell_check.bat` (BELL) | فحص وإصلاح بنقرة: الموقع، العنوان العام، أجهزة الجرس |
| `tunnel_here.bat` (BELL) | تشغيل نفق Cloudflare «iajaward» على هذا الجهاز (عند استبدال جهاز الخادم) |

### و) أسلوب التحديث
**القاعدة:** كل تعديل يُكتب ويُختبر ويُدفع إلى GitHub (`main`)، وأنت تشغّل `update.bat` فقط. أي تعديل يدوي على الكمبيوتر يُفقد عند التحديث.
- التطبيقات (Android / Desktop / المشغّل المكتبي) تُبنى تلقائياً في **GitHub Actions** مع كل دفع.

### ز) الأسرار
- كل نظام له `.env` في مجلده (لا يُرفع إلى GitHub): كلمة مرور الإدارة، `SECRET_KEY`، `BACKUP_DIR`، `CF_API_TOKEN`…
- **لا تُلصق الرموز ولا روابط قواعد البيانات في المحادثات.**

### ح) حسابات GitHub
| الحساب | المستودعات |
|---|---|
| `AcsVe` | `Attendance`، `Bell` |
| `baqjo` | `Library` |

## 3) نظام الحضور والانصراف — ATT (`3.iajaward.org`)

**ما هو:** حضور وانصراف الموظفين — ويب + تطبيقا أندرويد (الموظف Check-in، والإدارة Att Dashboard) + أجهزة بصمة ZKTeco (ADMS عبر الإنترنت أو السحب بالشبكة) + جهاز مدخل QR (Kiosk).

**أهم الميزات (حتى 2026-10-20):**
- البصمات الوسطى خروج/عودة، استراحة الغداء (عام ولكل قسم: تفعيل / عدم تفعيل / وقت خاص)، المغادرة المبكرة، «بدون سجل انصراف»، الانصراف التلقائي (معطّل افتراضياً).
- طلبات التصحيح من الموظف، الإجازات وأرصدتها، الكشف الشهري (بلا مبالغ)، الملخص اليومي للإدارة.
- المتابعة المباشرة بخرائط ملء الشاشة وطبقات، التتبع اللحظي للميدانيين (حتى ثانية واحدة)، يستمر التحديث عند مغادرة الصفحة.
- الصمود عند توقف الخادم (نبضة، مهلة، تخزين نقاط المسار على الهاتف وإرسالها لاحقاً)، تنبيه توقف جهاز البصمة.
- فتح الشاشة المعنية من الإشعار، طباعة بيانات الدخول من التطبيق، **شاشات العرض للمشاهدة فقط** (`/display/<رمز>`).

**الحالة:**
- آخر commit: `851bce8`؛ آخر APK: `1.0.18` (من `https://3.iajaward.org/app`).
- شغّلتَ `update.bat` ووصل إلى `851bce8`، وكان النظام متوقفاً ← المطلوب: `backup_now.bat` ثم `att_on.bat` (كمسؤول)، **ثم تأكيد أنه يعمل**.
- بعد التشغيل: تثبيت APK الجديد، مراجعة استراحة الغداء، أرصدة الإجازات، أوقات الملخص اليومي.
- لم يُختبر على أجهزة حقيقية: فتح الشاشة من الإشعار، الطباعة، تخزين نقاط المسار أثناء الانقطاع، التتبع كل ثانية.

**المؤجَّل:** الرواتب والخصومات (الخطة في `docs/payroll_plan.md`).

الدليل الكامل: **`Att.md`**.

## 4) برنامج التحليل المكتبي — `home.py`

**ما هو:** «نظام تحليل سجلات الحضور والانصراف» — برنامج ويندوز (tkinter) يقرأ قاعدة برنامج ZKTime (`att.mdb` / `att2000.mdb`).

**ما أُضيف:** قسم **«صيانة ملف att2000.mdb»**:
1. عدد السجلات والتواريخ.
2. حذف السجلات المكررة.
3. تقليص الحجم وإعادة الفهرسة.
4. حذف كل السجلات حتى تاريخ محدد.

**الحماية:** نسخة احتياطية تلقائية قبل أي تعديل، فتح حصري للملف، رفض التنفيذ وبرنامج ZKTime (`att.exe`) مفتوح، تأكيد بعدد السجلات قبل الحذف. التنفيذ عبر PowerShell (ADODB/JRO/DAO) دون الحاجة لـ pyodbc، ويجرّب نسختي 32/64-بت تلقائياً.

**الحالة:** أُرسل الملف؛ ليس في مستودع GitHub (أي تعديل لاحق يُرسل كملف).

## 6) نظام جرس الحصص — BELL (`5.iajaward.org`)

**ما هو:**
- تنبيه نصي وصوتي لكل شعبة بنهاية الحصة وبداية التالية — تطبيقات Android / Desktop / iOS / المتصفح، بأكواد الشعب والمعلمين.
- **الجرس المركزي (السمّاعات)** — مستقل عن التطبيقات والأكواد:
  - يرنّ ببداية كل حصة واستراحة؛ لكل توقيت (برنامج جرس أو مرحلة) نغمة حصة ونغمة استراحة: **22 نغمة مدمجة** (8 للحصص، 6 للاستراحات، **8 للأطفال**) + رفع WAV/MP3.
  - **رنّات حسب الوقت:** رنين باسم ووقت تختارهما أنت (طابور الصباح، نهاية الدوام…) بأيامه ونغمته وأجهزته — غير مرتبط بالحصص.
  - **تفعيل/تعطيل** على كل المستويات: الجرس كله، كل توقيت، كل حصة/استراحة وحدها، كل رنين حسب الوقت.
  - **أجهزة جرس متعددة:** خادم واحد للمدرسة، وفي كل مبنى جهاز جرس؛ لكل جهاز اسم ومفتاح وترخيص وتوقيتاته ومستوى صوته، و«رنّ الآن» على الأجهزة المختارة.
  - **جهاز الجرس = كمبيوتر + `BellPlayer.exe` 1.4** (تثبيت/تحديث بنقرتين، ملفات bat لكل الأوامر، توقيت الخادم، يعمل دون إنترنت، ترخيص ببصمة الجهاز) **أو علبة ESP32 بدون كمبيوتر** (Wi-Fi أو Bluetooth — البرنامج `device-1.0` مبني ولم يُجرَّب على قطع حقيقية).
- **إدارة الجداول:** إدراج حصة/استراحة **في أي مكان** من اليوم (لا في آخره فقط) في المراحل وبرامج الجرس.
- **حماية الصفحات:** HTML مشفّر، ومنع F12 وعرض المصدر والزر الأيمن.
- **أدوات:** `bell_check.bat` (فحص وإصلاح)، `install_bell.bat` (خادم على جهاز جديد بملف واحد)، `tunnel_here.bat` (نقل نفق Cloudflare إلى الجهاز)، «تنزيل كل البيانات».

**ما تمّ:**
- 2026-10-21: النقل من Render إلى الكمبيوتر (`C:\Bell`، 8005) ونقل بيانات Neon بنفس الأكواد (151 معلماً، 20 شعبة، 12 صفاً، 11 برنامجاً)؛ النسخ إلى `G:\My Drive\RAS-Bell\db` + نسخة دائمة في `neon-original\`؛ جهاز المكتب متصل ومرخّص حتى **2027-10-21** (البصمة `4C7758C688A6DE55`).
- 2026-10-22: BellPlayer 1.3/1.4، أجهزة متعددة، نغمات الأطفال، رنّات حسب الوقت، التفعيل/التعطيل، الإدراج في الوسط، برنامج ESP32 وصفحة البرمجة عبر Bluetooth، أدلة التجهيز.
- آخر commit: `09995e0`. الملفات الجاهزة: `https://github.com/AcsVe/Bell/releases/tag/apps` (BellPlayer.exe، install_bell.bat، التطبيقات).

**المتبقي (بالترتيب):**
1. **الخطأ 1033:** نفق Cloudflare `iajaward` يجب أن يعمل على جهاز الخادم وحده — وهو يخدم **كل** عناوين iajaward.org (الجائزة، ATT، الجرس). إن كان الجهاز الجديد بديلاً كاملاً: `tunnel_here.bat` عليه، ثم تثبيت الجائزة وATT عليه أيضاً.
2. `update.bat` ثم `3_autostart.bat` (كمسؤول) على جهاز الخادم.
3. تحديث BellPlayer إلى 1.4 على جهاز المكتب + «رنّ الآن».
4. التحقق من النسخ كل ساعة في `RAS-Bell\db`.
5. `BELL_SERVER` في GitHub + إعادة بناء التطبيقات + تحويل الأجهزة الحالية (قبل إيقاف Render).
6. الهاتف الاحتياطي (`BELL_REMOTE="gdrive:RAS-Bell"`).
7. أجهزة المباني الأخرى؛ وجهاز ESP32 بعد شراء القطع (شاشة **I2C بأربعة دبابيس**، PCM5102A مع لحام الدبابيس والوصلات، بطارية LIR2032).
8. بعد أسبوع من التأكد: إيقاف Render وNeon.

الأدلة: **`docs/Bell.md`** (التقني) — **`docs/Bell_Deploy.md`** (خادم + أجهزة متعددة في بيئة جديدة) — **`docs/Bell_Hardware.md`** (علبة ESP32).

## 6ب) نظام براءة الذمة والعهد العينية — CLEARANCE (`6.iajaward.org`)

**ما هو:** بديل سكربت Google Apps Script وورقته — نماذج براءة الذمة، والعهد العينية، وسجل الموظفين، لعدة منظمات.
- **براءة الذمة:** نموذج لكل موظف مستقيل ← بريد لكل قسم برابط توقيع خاص (دون دخول) يعرض عهد الموظف لدى القسم ← خالية/معلق ← عند الاكتمال بريد للموظف وشؤون الموظفين والمحاسبة ← تذكير (يدوي وتلقائي كل 3 أيام)، إقفال، إلغاء، إرسال للمحاسبة ← بوابة المحاسبة (تسوية وإقفال) ← طباعة «نموذج براءة الذمة» أو «إثبات تسوية مالية».
- **العهد:** تسليم/استرجاع بإشعارات، إيصالات مطبوعة، استيراد قوائم، وصفحة «عهدي» لكل موظف.
- **الموظفون:** إضافة، لصق قائمة من Excel، رفع Excel/CSV، نقل بين الأقسام، إنشاء حسابات دخول جماعياً.
- **الواجهة:** كل القوائم برؤوس ثابتة وتصفية لكل عمود وترتيب وتحديد جماعي (تفعيل/إيقاف/حذف…)، لوحة رئيسية بأرقام قابلة للضغط، المستخدمون كبطاقات تُظهر مهام كل دور.
- **البريد:** Microsoft Graph (نفس تسجيل التطبيق الذي يستخدمه نظام الحجوزات؛ `1_setup.bat` يأخذ الإعدادات منه تلقائياً).
- **استيراد Google Sheet القديم:** من الإعدادات أو `ops\import_sheets.py` (الأقسام، النماذج، الردود، العهد؛ التواريخ الهجرية تُحوَّل).

**ما تمّ (2026-10-22):** بيئة التشغيل كبقية الأنظمة (bat، النفق، النسخ، الهاتف)، SQLite، الوحدات كلها أعلاه. آخر commit: انظر `AcsVe/Clearance`.

**المتبقي:**
1. على الكمبيوتر: تنزيل المستودع إلى `C:\Clearance` ← `1_setup.bat` ← `3_autostart.bat` (كمسؤول).
2. تنزيل Google Sheet القديم كـ Excel واستيراده.
3. الأقسام وبريدها، ثم الموظفون، ثم حسابات مسؤولي الأقسام.
4. تجربة نموذج كامل على موظف تجريبي، ثم إيقاف سكربت Google القديم.
5. الهاتف الاحتياطي (`clearance-standby`).

الدليل: **`docs/Clearance.md`**.

## 9) ملاحظات لأي وكيل/مطوّر يكمل العمل
- **اللغة:** الردود للمستخدم بالعربية الفصحى؛ الواجهات عربي/إنجليزي.
- **أسلوب العمل:** تعديل ← اختبار ← commit ← push إلى `main`؛ المستخدم يشغّل `update.bat` فقط.
- **المنافذ المحجوزة:** 8000 الجائزة، 8001 التذاكر، 8002 الحجوزات، 8003 ATT، 8004 المكتبة (مقترح)، 8005 BELL، 8006 CLEARANCE.
- **أي نظام جديد** يتبع نفس القالب: `serve.py` (Waitress)، `ops/` (`common`, `setup_local`, `backup`, `restore`, `cf`)، ملفات bat، `standby/phone.sh`، نفق احتياطي باسم `<النظام>-standby`، نسخ إلى `IAJ-backups\<النظام>`.
- **قاعدة البيانات على الكمبيوتر SQLite دائماً** (لا Render ولا Postgres للإنتاج).
- **لا تستخدم رموز وصول مُلصقة في المحادثة.** الوصول إلى GitHub عبر صلاحيات الجلسة.
- رسائل الـ commit تنتهي بأسطر النسب المطلوبة في الجلسة.
